# 중복 지급 의심 확인

## 원장 대조

같은 사용자·재화·참조 대상의 원장 항목을 비교한다. 전투 보상은 `referenceType=battle_session`, 운영자 지급은 `referenceType=operator_grant`로 구분한다. 항목이 비슷한 시간에 두 건 있다는 이유만으로 중복으로 확정하지 않는다.

## 판정 원칙

같은 업무 요청의 멱등성 키와 거래 참조가 일치하는지 확인한다. 잔액의 `balanceAfter`가 기록 순서와 맞는지도 살펴본다. 데이터가 잘렸거나 키가 없는 과거 기록은 의심 상태로 남긴다.

## 운영자 대응

AI 분석만으로 재화를 회수하거나 추가 지급하지 않는다. 관련 원장 ID와 잔액 변화를 정리해 담당 운영자에게 전달하고, 정정이 필요하면 별도 승인과 감사 기록이 남는 지급 절차를 이용한다.
